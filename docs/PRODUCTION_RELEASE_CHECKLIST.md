  - ⛔ **No production place to run inference.** `onnxruntime-node` ships glibc binaries only and does not load on the Alpine (musl) API image (root cause shown in the audit, section 3.3); and BiRefNet lite peaks at 2.4 to 4.4 GB per picture (fixed 1024 px input) against a 2 GB `t4g.small` (API container limit 420 MB). A glibc image alone does not fix it: a separate, memory-sized inference service, or a commercial API behind our API.
  - ⛔ **No usable browser model** (the 512 exports gave poor or empty masks, WebGPU gave none, the 1024 model runs out of memory in WASM).
  - **Limits that must be known (and either fixed or accepted by the owner) before any release of this feature:**
    - ☐ Tested only in headless Chromium on macOS. Safari, Firefox, Windows, Android and real iPhones/iPads are UNTESTED (compatibility matrix: audit section 6.3). iOS canvas limits are handled by a probe and conservative per-device pixel limits but have never run on a device.
    - ☐ Memory at the size limit (up to 25 MP on desktop, 16 MP on phones/tablets, 8 MP on low-memory devices) is an estimate, never measured; the preview now holds an extra full-size bitmap (about +100 MB at 25 MP). Needs measurement at 4, 12 and 25 MP on a low-end laptop and a mid phone, and a 20-cycle memory-stability run.
    - ☐ Edge refinement is judged on synthetic scenes and one real photo only. On the real photo the refined edge is crisp but slightly aliased on a light background, and the blurred fingertip area shows some speckle. It cannot recover thin hair the model lost entirely, and it leaves the mask unchanged where subject and background colours are alike. No hair/animal/product image set has been run (test plan: audit section 6.2; acceptance numbers there are PROPOSALS, not agreed).
    - ☐ Painting is pointer-only (no keyboard path); the wheel-zoom choice is a heuristic (a notched mouse wheel vs a trackpad scroll) with a preference to override it.
    - ☐ Cancelling or timing out kills the model process, so the next picture reloads the model (about 30 s on the development machine); idle processes are retired after 5 minutes (`CUTOUT_IDLE_MS`). In production this cost depends on the chosen provider.
    - ☐ A picture that is already transparent cannot get back areas whose colour was lost; "Apply to slide" may scale the PNG down to fit the 8 MB upload limit (Download keeps the original size); the assistant's "remove the background" still uses the server model and is gated by the same flag.
    - ☐ The rate limiter and the model queue counter are per process (fine for one API task, must move to a shared store before a second instance).
    - ☐ Provider key protection, retention, user-image privacy text, DPA and sub-processor entry are not written yet (needed the moment any provider sends the picture off our server: audit section 7.1).
  - To turn it on: approve a provider (evidence in code), run the audit's test plan on it, fill the commercial checklist, update this entry. Until then the endpoints answer "not available" and change nothing.
