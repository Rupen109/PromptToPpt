# Object animations, transitions and Morph

Owner spec: PowerPoint-style animation. Since 2026-11-09 (see `PLANS_AND_FEATURES_V5.md`) **object animations, the Animation pane and the basic transitions are open to every plan**; only **Morph** (transition type `morph`, the Morph layouts and Morph tools, `features.morph`) is Gold and Premium. A deck with Morph keeps playing after a downgrade; Morph can be removed but not added or changed (the server refuses it on save).

## How it works
- **Data** (`packages/validation/src/presentation.ts`): `slide.effects[]`, one list per slide in play order. Each effect has its own id, the `elementId` it plays on, `category`, `type`, `start` (`click` | `with` | `after`), `duration`, `delay`, `easing`, and the options its type understands. Absent on every slide saved before this (no version bump).
- **Catalogue** (`packages/ui/src/motion/catalog.ts`): the one table of effects: label, which options each understands, whether the end state stays, which element types it works on. The editor reads it, so no control is shown for an option an effect ignores. Nothing is added to the schema list before the engine plays it.
- **Timeline** (`timeline.ts`): turns the list into steps. Step 0 is automatic (before the first On Click); each On Click starts a step; With Previous shares the previous start, After Previous follows the previous end; delays are added.
- **Keyframes** (`keyframes.ts`): transform / opacity / clip-path / visibility only. Entrances start hidden and end visible, exits end hidden, one-off emphasis ends where it began.
- **Player** (`player.ts`): no timers. A step is handed to the browser's animation clock with offsets; click while moving finishes it; Back takes one step back at once; `showAll()` for a slide you come back to; `destroy()` cancels everything. The saved slide is never touched.
- **Renderer** (`SlideCanvas` prop `effects`): elements with effects sit in a wrapper `data-pt-el`, hidden from the start when their first effect is an entrance; the theme's entrance steps aside on such slides (ambient loops stay).
- **Editor commands** (`apps/editor/src/editor/effect-commands.ts`): add / update / remove / duplicate / move; adding an effect marks the slide hand-edited so a theme swap keeps its elements. Deleting an element, laying the slide out again, or an AI rewrite removes the effects that would point at nothing. Duplicate Slide copies effects with new ids pointing at the copy's elements.
- **Server gate** (`services/api/src/billing/animation-gate.ts`, save route): effects may not be added or changed without the `animations` feature; judged against the stored deck, key-order independent.

## Morph
- **Matching** (`motion/morph.ts`): the same element = same id and same type, never by words, picture or name. Duplicate Slide keeps element ids (an id only has to be unique within its slide); SVG gradient ids include the slide id so two slides on one screen cannot collide.
- **Drawing** (`motion/MorphLayer.tsx`): both slides on one canvas. Every matched element is two copies, each carried onto the other's place with `transform` and `opacity` only (boxes by corner and size; text by its centre and an even scale by font size, so words never stretch or reflow). One clock (Web Animations), nothing laid out while it plays, nothing saved. An element on one slide only comes in or goes out; the backgrounds cross over.
- **Fading:** a copy fades in over the old one, which stays solid underneath (no dip). Text whose words change, or that wraps differently in its new box, cross-fades instead (a brief overlap in the middle is inherent).
- **Present mode:** forward uses the destination slide's transition; backward plays the leaving slide's in reverse. A key pressed during a Morph finishes it. The destination's own effects start afterwards. Reduced motion: no overlay.
- **Choice kept:** `transition.own` marks a transition a person (or Morph generation) set; re-layout, theme swap and AI rewrite keep it, where a transition taken from the theme is replaced.
- **Gate:** a Morph may not be added or changed without the `animations` feature (same rule as effects).
- **PPTX export:** a Morph slide is written as PowerPoint's own Morph transition (see "What PPTX export does"); anything that cannot play it shows a Fade.

## Morph layout family (decided 2026-11-05)
Twelve layouts drawn from ONE cast (title, kicker, hero picture, up to four cards each with number/heading/text, accent shapes, one stat) with the same element ids on every slide of a Morph deck: cover, hero left, cards in a row, cards stacked beside the hero, 2×2 grid, spotlight (one card enlarged), timeline, big stat, compare, focus hero, quote, closing. The model writes the 3-4 concepts once and orders the scenes; the code enforces the rules (cover first, closing last, no layout more than twice in a row, spotlight only after an overview), assigns ids and sets Morph transitions on slides 2 and up; a built-in story order is the fallback. Used only when the Morph switch is on, and offered in the layout picker for Gold and Premium. The twenty existing layouts are unchanged.

## How the Morph scenes are built (M2)
- `layout: 'morph'` is ONE layout id; `content.scene` is one of the twelve (`MORPH_SCENES`). It is left out of `GENERATABLE_LAYOUTS` (ordinary decks never get it) and out of the assistant's layout list. The "same layout 3 times in a row" rule counts scenes.
- Every part has a fixed id (`m-title`, `m-kicker`, `m-sub`, `m-hero`, `m-c0…m-c3` with `-n` / `-h` / `-t`, `m-stat-value`, `m-stat-label`, `m-accent-1`, `m-dot-i`, `m-decor`, `m-logo`), whatever id generator is used. A card's background parts are named by the theme's own card style, so the look follows the design.
- No element carries an entrance animation: a Morph deck moves by its transitions. Every Morph slide arrives with `{type:'morph', duration:1200, easing:'power2-in-out', own:true}`.
- Dramatic scenes (cover, focus-hero, closing) use the design's title background; the others its body background. The picture is the deck's one picture (a colour block stands in when there is none).
- When the words do not fit (a squarer canvas, long text) the scene is drawn again with less: first without kicker and subtitle, then also without card numbers. Text that still does not read against what is really behind it is recoloured.
- Measured on the real scenes: between card scenes 19 of ~20 elements are matched, so cards move and regroup. Cover → picture scenes share fewer parts (mostly crossfade).
- Not reachable yet: nothing creates a Morph slide until M3 (generation and the create-page switch) and the layout picker (phase 4) land.

## Morph scenes, redesigned (2026-11-08, after the owner's feedback)
The first scenes moved the same cards between very different shapes (a wide card, a thin list row, a mini card), so the Morph had to stretch and cross-fade them and the slides did not feel connected. The scenes are now built from RIGID parts:
- **Cards** are one fixed-proportion tile (500 × 380 at scale 1). A scene only chooses a position and one scale. Text is fitted ONCE per deck (one heading size, one body size, measured a little narrower than the box), so it wraps the same way at every scale and a Morph is a clean move and resize. A card too small to read its body (under about 20 px) shows number and heading only; its body fades out first when it leaves its big form and in last when it arrives.
- **The picture** is always 4:5 and only ever scales, so it never re-crops.
- **The header** (kicker, title, subtitle) is in the same place at the same size on every content scene; only the cards and the picture move.
- **Motion:** default 900 ms; the cards leave a little apart (7% of the duration each) and arrive together; a text whose words change fades out, then the new one fades in (no overlap).
- Tests assert these properties (`morph.test.ts`: wrap ratio constant across scenes, picture 4:5, header unchanged, body shown only when big).

## How a Morph deck is generated (M3)
- **Job option** `morph` (new presentations only; remix, rewrite and pictures-only are refused). The server checks the plan (`assertAnimations`), never the browser. The create page shows the option on the length step to every plan: a checkbox on Gold/Premium, a locked button with the upgrade prompt on the others. It sits above the length buttons because choosing a length starts the build.
- **Pipeline** (`generation/pipeline.ts`, `morphDeck` branch): analysis and design as for any deck → ONE model call (`morphPlanPrompt`, request type `outline_generation`) returns the 2-4 concepts, the ordered scenes with their words and speaker notes, and what the hero picture should show → `sanitizeMorphPlan` → the slides appear at once (colour block for the picture) → the hero is looked up (the normal picture session, one request) → final write. No outline call, no slide batches, no critic: one call instead of one per batch.
- **Rules the code enforces** (`generation/morph-plan.ts`, never left to the model): exactly the asked number of scenes (a short plan is filled from the built-in story); cover first, closing last; a spotlight only after the concepts were shown side by side, each on a different concept in turn; never the same scene three times in a row; a quote only when the user supplied a real quotation; a big stat only when the user supplied a figure; figures the user never gave are removed from the words. If the model's plan is unusable, the built-in story order is used.
- **The cards are the same on every slide.** Condense (the shorten-on-overflow pass) never touches a card on a Morph slide, and small card text does not trigger it (it only drops the subtitle and kicker and shortens the title). Waiting cards on a spotlight and the concepts on a hero-left slide show number and heading only.
- **Ids**: the final build does not rename Morph elements (the progressive-write renaming is for ordinary slides). `harmonizeType` skips Morph slides (their scenes keep their own scale).
- Cost: one call, so a Morph deck costs less to make than an ordinary one; the credit estimate is unchanged.

## The editor workflow (2026-11-12)
- **Two ribbon tabs** under the toolbar (`ui.ribbon`): Animations (`animation/AnimationsRibbon.tsx`) and Transitions (`TransitionsRibbon.tsx`). One at a time; the Animation pane, Selection pane and Morph panel are right-hand drawers (`ui.drawer`).
- **Active effect** (`ui.activeEffectId`, resolved by `activeEffect()` in `editor/animation-model.ts`): the effect the Timing group and Effect Options edit. It is the one picked in the pane while its object is selected, otherwise the first effect of the selected object.
- **Gallery click** = `applyEffect` (`editor/effect-commands.ts`): one effect per selected object in selection order, ONE undo step; an object that already has an effect of that kind has it replaced (start, timing and easing kept). `addAnimation` adds another effect to the same object. `clearEffects` is "None". `paintAnimation` is the Animation Painter. All are pure, refuse locked slides and objects, and record nothing when nothing changes.
- **Model additions** (all optional, so older decks load unchanged): effect `path` (2-100 points as offsets from the object, canvas units; category `path`: `path-line`, `path-arc`, `path-turn`, `path-circle`, `path-custom`), `textBy` (`object|paragraph|word|letter`) with `stagger`, `trigger` (id of the object whose click plays it; it leaves the click sequence), `loop` (until end of slide), corner `direction`s, new effects `grow-turn` and `blink`; element `label` (the name from the Selection pane; never used for Morph matching, only ids are); transition `advanceAfter` (ms) and `advanceOnClick`.
- **Engine** (`packages/ui/src/motion`): `paths.ts` (presets, sampling, stroke thinning), `compileTriggers`, loops (never block a click), text parts (`data-pt-part` p/w/l drawn by `SlideCanvas` only on slides played with effects), `SlidePlayer.trigger/hasTrigger/skipTo`, directional transition keyframes (`pt-t-push-up` etc.), `MorphHandle.seek/replay` for the scrubber.
- **Present mode and the shared view** use the same player: triggers on click, advance after N seconds (the current slide's transition), "On mouse click" off, effects, loops.
- **Previews run on the canvas in place** (`CanvasPreview`, `StageOverlays`) and never touch the document.
- **Pane**: rows are memoised (a slide with 100 effects: pane opens in about 120 ms, applying an effect about 75 ms, no long task during a bar drag). Bars are dragged (pointer capture, snapped to 0.1 s) or moved with the keyboard (Left/Right = delay, Shift+Left/Right = duration). The pane, Selection pane and gallery own the arrow and Delete keys (`data-own-keys`); the pane stops those keys so the page's Delete handler never deletes the object too.
- **Morph check** (`editor/morph-check.ts`, pure): moving / fading in / fading out, warnings (duplicate names, text without a partner, picture changes, kind differs), suggestions from the same name / words / picture, fixes `matchToPrevious` (the object takes the partner's id, its effects follow) and `unlinkElement`; `addMorphScene` adds a slide from the twelve Morph layouts reusing the previous Morph slide's cards.
- **Plans in the UI**: Pro/Starter see Morph locked (lock icon, "locked, Gold plan" name, the upgrade window); a deck that has Morph keeps it, its settings are disabled and "Remove Morph" works.

## Morph by word / by character (2026-11-12)
- **Data**: `transition.by` = `object` (absent, the default) | `word` | `character`; Morph only, saved with the transition, so the server gate treats a change like any Morph change (Gold and Premium).
- **Plan** (`motion/morph.ts`): `piecesOf` splits a text exactly as the renderer marks it (words = runs of non-space characters of each run; letters = the characters of those words), `matchPieces` pairs equal pieces in reading order (longest common subsequence, case-insensitive; the rest are left over), `planPieces` decides whether a pair of texts may travel in pieces. A pair falls back to one object (with the usual cross-fade) when the texts are not both plain text, turn at different angles, have more than 60 words / 140 letters, or share less than a third of the shorter side's pieces (or nothing).
- **Drawing** (`MorphLayer`): both copies of such a text are drawn with their pieces marked (`data-pt-part`), every piece is measured BEFORE anything moves, and then only the NEW copy's matched pieces animate (from where the old piece was, scaled by the font-size ratio, to their own place); the old copy's matched pieces are hidden so there is exactly one of each; unmatched old pieces fade out, unmatched new pieces fade in during the second half. One clock, `transform` and `opacity` only, like the rest of Morph.
- **Editor**: Transitions tab, Effect options, "Morph: By object / By word / By character" (disabled on a plan without Morph, like every Morph setting); the Morph panel warns for each text that fell back and says why. Preview, scrubber and Present mode all use `MorphLayer`, so they play it the same way.
- Tests: `morph.test.ts` (tokens, matching, fallbacks, the caps), suite 67 W1 to W6 (positions sampled at 0, 30, 50 and 100 percent of a running Morph: the start of a travelling word equals its old place within 3 px, the middle is halfway within 25 px, the old copies are hidden, unmatched pieces fade).

## Hidden objects (the eye)
- `element.hidden` (optional). Not drawn anywhere: `ElementView` returns nothing for it, so the editor canvas, thumbnails, Present mode, the share link, PDF / PNG / HTML export (they render the same view) and Morph (`planMorph` ignores hidden objects) all leave it out; the server's PPTX export skips it (`pptx-hidden.test.ts`). The Animation pane / player treat it as absent: its effects play nothing and take no click.
- Selection pane: an eye button per object (a locked object or slide refuses), the row is dimmed and announced as hidden; undo restores it.

## Animations follow their objects when a slide is redrawn
- A re-layout, a design / theme swap, an AI rewrite or placing a picture redraws the slide with NEW element ids. `remapEffects` (effect-commands.ts) moves each effect (and trigger) to the element that takes its place: the same id when the new slide keeps it (Morph decks), otherwise the same kind of object in the same role and the same place in reading order for text (by role), pictures, charts and tables. Shapes and icons have no identity beyond their id, so their effects are removed.
- Adding an effect no longer marks the slide hand-edited (that was only there to keep ids stable), so such a slide can be redrawn.
- When some effects cannot be kept (the slide is still there but at least half of its objects were replaced and some effects lost their object) the editor says how many and that Ctrl+Z brings them back (`lostEffects`, a toast from EditorPage). Deleting a few objects by hand is not announced.
- Tests: `animation-workflow.test.ts` (re-layout, design swap, rewrite, no successor, stable ids, hand deletion), `effect-commands.test.ts`, suite 67 R1.

## Small screens
- The ribbons wrap and scroll inside a capped height (36 vh, 46 vh from 1280 px up). Below 1024 px the Animation pane, Selection pane and Morph panel open as a bottom sheet (48 vh) instead of a side column, so the ribbon above stays reachable. Checked at 1920, 1280, 1024 and 768 wide: no horizontal page scroll, no overlap.

## What PPTX export does with all this (exactly)
Export to PowerPoint (server: `export/pptx.ts` builds the shapes, `export/motion.ts` + `export/effects-xml.ts` write the animation into the finished zip) carries the deck's animation, transitions and Morph. Every exported object is named `pt:<elementId>`; the post-processing step turns those names into shape ids and writes, per slide, `<p:transition>` and `<p:timing>`.

**Object effects -> `<p:timing>`.** The steps come from the editor's own `compileTimeline` / `compileTriggers` (`@prompttoppt/ui/motion-core`), so the file plays the steps the editor plays: step 0 (before the first On Click) starts when the slide appears (`onBegin`), every On Click is one outer `<p:par>` with `delay="indefinite"` (`clickEffect`), With Previous is `withEffect`, After Previous is `afterEffect` in a new inner `<p:par>` that starts when the previous effect ends, the effect's own delay is the effect node's start delay, duration is the behaviour's `dur`. Each object with effects gets one build group per effect (`grpId` + `<p:bldP>`; charts `<p:bldGraphic>`; pictures and tables have none). A trigger object ("click this to play") is one `interactiveSeq` per trigger, aimed at the trigger's shape. The theme's own automatic entrance still exports for objects that have **no** effects of their own (the editor plays an object's own effects instead of its theme entrance). Hidden objects are not exported and their effects are not written.

|---|---|---|

Our distance in canvas px is written as a fraction of the slide (PowerPoint's own Fly In starts off the slide). A Wipe has four sides: a corner direction uses its horizontal side. Float with a left / right direction is written as the upward Float. |
| Pop In | no built-in; written as scale (0 -> overshoot -> 1) + fade, shows as a custom effect | - |
| Pulse, Grow / Shrink, Spin, Teeter, Blink, Transparency | Pulse 26, Grow/Shrink 6, Spin 8, Teeter 32, Blink 35, Transparency 9 | Pulse has no slight fade dip (PowerPoint's own has). **Transparency** is written the way PowerPoint writes its own: the level is set at once and holds; there is no gradual fade (ours fades over its duration). |

Timing options: easing becomes smooth start / smooth end (`accel` / `decel`: ease-in 100 / 0, ease-out 0 / 100, ease-in-out and power2-in-out 50 / 50, ease 25 / 75). *Back-out's overshoot cannot be written*, it ends with a smooth stop; effects with their own curve (Bounce, Shake, Teeter, Blink, Pulse, Transparency) are written without an easing. Repeat N = `repeatCount`, loop = `repeatCount="indefinite"`, Rewind = `autoRev` (emphasis and paths only, as in PowerPoint). **By paragraph** = one effect per paragraph aimed at its paragraph (`pRg`), the later ones With Previous `stagger` ms apart, `build="p"`. **By word / by letter** = the effect's `<p:iterate type="wd|lt">` over the whole text, `tmPct` = stagger / duration (PowerPoint's own "by word / by letter" mechanism, not per-character ranges; it needs no text ranges and cannot go out of step with the text). A text that cannot be split (one paragraph, or an object that is not text) is written as the whole object. After Previous follows our timeline (starts when the previous *effect* ends); PowerPoint, if a person edits the animation there, recomputes After Previous as "after the whole previous group", which differs only when a With Previous effect finishes earlier than the one it accompanies.

**Transitions -> `<p:transition>`** (inside `mc:AlternateContent` as PowerPoint 2010+ writes it: `p14:dur` = exact milliseconds, plain `spd` fast <= 0.7 s, medium <= 1.2 s, slow beyond, as the fallback): Fade -> Fade; Slide -> Cover; Push -> Push; Wipe -> Wipe; Zoom -> `p:zoom dir="in"` (what PowerPoint calls "Box In": the nearest built-in to our scale-and-fade); None -> none. Directions: the editor stores where a slide / push / wipe comes FROM, PowerPoint's `dir` names where it MOVES (from left = `r`, from right = `l`, from top = `d`, from bottom = `u`); defaults are as the player's (slide and push from the right, wipe from the left). "Advance on click" off = `advClick="0"`, "advance after" = `advTm` in milliseconds. A transition's own easing is not written.

**Morph -> PowerPoint's Morph** (`mc:AlternateContent` with `Requires="p159"`: `<p159:morph option="byObject|byWord|byChar"/>` and a Fade fallback, duration in `p14:dur`). Needs PowerPoint 2019 or Microsoft 365; older PowerPoint versions (and anything else that reads the file) play the Fade. PowerPoint pairs shapes between two slides by their names, so an object that is the same object here (same id and same type) on the Morph slide and the slide before it gets the name `!!pt:<elementId>` on both (a second shape of one object gets `#2`); names are unique inside a slide. Everything else keeps its `pt:` name and PowerPoint's own content matching applies to it. PowerPoint's Morph engine is its own: the "cross" blend, our easing and the exact piece-by-piece travel of text are PowerPoint's choices, not ours.

**Not written:** the ambient loops (Ken Burns, float, drift), the "back-out" overshoot, transition easing, Transparency's gradual fade, effects on hidden objects, sounds. PDF / PNG / JPG / HTML exports are static pictures of the slide as the editor shows it (hidden objects left out, objects with an entrance effect shown in their final state).

**Safety.** Every slide's XML is checked before it is written (well-formed, every animation target is a shape of that slide). Any problem with one slide's effects leaves that slide without `<p:timing>` (its transition and shapes stay); any other problem leaves the slide exactly as pptxgenjs wrote it. A file PowerPoint would offer to "repair" is worse than one without animation.

## Morph templates (Space, Product Launch, Education, Cool Morph, Business Plan)

A Morph template is the choreography of a whole deck (`packages/theme/src/morph-templates`): per scene, where every object is, its size and rotation, and which objects are the same object on the next scene. Geometry and text styling come from a source deck, never its pictures; the pictures are ours (`pictures` by hash), the words are `fields`. `composeTemplateScene` turns a scene into slide elements, with `blend: 'cross'` (PowerPoint-style crossfade) and `durationMs: 1500`.

- **Import:** `scripts/morph-import.mjs <deck.pptx> data/<name>.ts` for a PowerPoint deck; `scripts/morph-import-canva.mjs <canva view?embed url> data/<name>.ts NAME --font X --body-font Y` when only a Canva link exists (it opens each slide in a headless browser, measures every object, and checks by pixels which pictures are really painted).
- **Artwork:** `scripts/gen-morph-photos.mjs [--only name,name]` makes the pictures with a Gemini image model (`gemini-3-pro-image`, ~$0.13 each) into `apps/web/public/morph-templates`. Cut-outs are made on a flat key colour and keyed out; glows and planets use their brightness as transparency; the script rejects cut-outs sliced by their frame and retries. `scripts/gen-space-assets.mjs` makes the Space star field and planet line-up.
- **Cache:** bump `MORPH_ART_VERSION` in `compose.ts` whenever a picture is regenerated (files are cached for a day; the version is in each picture URL).
- **Typography rules (ours, not the source's):** body copy lifted to a readable size with a 1.4 line height, headlines semibold (or the template's `headingWeight`), lines that were one line in the source stay one line, tickers rest inside the margins.
- **Public page:** `/morph-animation-templates` (live previews, FAQ with JSON-LD, sitemap, llms.txt). Add a template to `registry.ts`, `demos.ts` (sample copy per scene) and the FAQ in `apps/web/lib/morph-page.ts`.
- **Tests:** `morph-templates.test.ts`, `demos.test.ts` (theme), `morph-template-assets.test.ts` (API: every picture file exists, every SVG is safe).

## A whole deck from a Morph template (Gold and Premium)

**What it is.** On the create screen, with "Morph animation" on, the person picks "AI plans it" (the 12 generic scenes and one picture) or one of the designed templates. Links from the website's template pages (`Use this template`) arrive as `/?morphTemplate=<id>` on the editor's home page and preselect it. The job option is `morphTemplate` (implies `morph`: same plan gate, same monthly allowance counted from `generation_job.options->>'morph'`).

**Who writes what.** The template decides everything that moves (its scenes, objects, ids, pictures, Morph). The model writes only the words, in ONE call (`templateFillPrompt`, request type `outline_generation`; a second small call only when some boxes are too long). No outline, no slide batches, no design call, no picture search: the pictures are the template's own cached files, so a template deck costs one text call.

**What the code guarantees** (`services/api/src/generation/template-deck.ts`, not the prompt):
- every box gets only as many letters as it can hold (`room`, wider for bold and capital type); a word is never cut in the middle; a cut never ends on "and", "&", "of"…
- a figure the request never gave is removed; boxes that hold only a figure (40%, 2026) are left empty unless the request gave it; boxes that hold a detail only the user can give (address, phone, e-mail, handle, credit) are left empty and the object is not shown (`fields[id] === ''`);
- the template's own wordmark and date line (e.g. "Seed deck · 2026") are replaced once for the whole deck or left out ("branding" boxes, `chromeSlots`);
- a ticker (one phrase the template repeats) gets one short phrase;
- sample sentences of the template (about another subject) are never used as a fallback.

**Limits.** 16:9 only (the templates are drawn at 1920 x 1080); the template's scene count is the deck's length (11 to 20 today; it must be within the plan's slide limit: Gold 25, Premium 60); the template's navigation labels (small repeated menu words) stay in the template's English unless they are branding boxes; where a figure box is left empty its small caption stays.

**Tests.** `services/api/src/generation/template-deck.test.ts` (helpers), `generation.test.ts` (gates, quota, one call, scenes/ids/pictures, no placeholder, saves clean), suite `e2e/suites/68-morph-template-deck.mjs` (website link, home chip, picker, real build in about 12 s, opening, editing, Pro locked).

## Choosing a template from the topic ("Best match for my topic", 2026-11-18)

**What the person sees.** With Morph on, the picker offers "AI plans it" (still the default), "Best match for my topic" (never on by default) and the template grid. Choosing "Best match" shows the recommended template (poster, slide count, one plain sentence of why), up to two close alternatives, or "no designed template fits, the deck is designed for your topic". The length step then shows that template's real slide count; the length buttons wait while the answer is coming.

**Why it is decided before the deck starts.** The template fixes the slide count, the credits reserved and the deck's first frame, all settled when the job is created. So `POST /api/v1/generation/morph-match` (Gold and Premium, 12 a minute, 200 model calls a day, answers cached 10 minutes) decides, the create page shows it, and the job only ever receives a concrete `morphTemplate` id (validated again by the existing start rules). One decision function, `services/api/src/generation/morph-match.ts`.

**How it decides.**
1. *Hard filters (code):* templates longer than the plan's slides per deck (Gold 25, Premium 60) or costing more credits than the balance even at the cheapest model tier; languages the template fonts cannot set (only Latin-script languages match; Arabic, Hindi, Chinese, Vietnamese and the rest always get a custom deck); an explicit light or dark request; and the template's PICTURES: `MORPH_PROFILES` (`packages/theme/src/morph-templates/profiles.ts`) says whether a template's art is `abstract` (any subject), `themed` (a loose world) or `subject` (one subject: planets, a drinks can, a microscope). A subject template is offered only when the request uses words of that subject, so a tax guide never gets a soda can.
2. *Score (pure, tested):* the template's own topic words, the deck family the request's category belongs to, the picture world, how close the template's length is to a length asked for, and figures (scenes built around a number stay empty when the request has none). Every score comes with readable reasons.
3. *One small model call* (`morph_match`, fast route) chooses between the closest three or answers "none"; it judges pictures and story, not the name. If it fails, a strong score (55+) is enough, otherwise the deck is custom. A low confidence also becomes custom.
Anything that does not fit well is a **custom deck** (the AI-planned Morph, in the topic's colours): a poor template is never forced.

**Adding a template.** Add its `MORPH_PROFILES` entry (the test fails without it), its `topics` (8 or more), `category` and `audience`; then add golden-set rows for the requests it should win.

**Tests.** `generation/morph-match.test.ts` (a golden set of 40 requests: the templates a person would accept, or custom; subject templates never offered for another subject; plan, credit, mood, language and length filters; the decision with a stubbed model), `routes/morph-match.test.ts` (auth, Gold gate, schema, cache, no model call for a language that cannot match), `profiles.test.ts` (every template has a profile). Checked by hand with the real model: a Series A pitch → Market Pitch (with its reason and two alternatives), a tax guide → custom, Arabic → custom; the answer takes 1 to 3 seconds, 6 ms when cached.

### Which scenes a template deck shows (shorter decks, scenes the request cannot fill)

A template is drawn with a fixed story (11 to 20 scenes). `packages/theme/src/morph-templates/scenes.ts` (`chooseScenes`) decides which scenes a deck shows; `services/api/src/generation/morph-scenes.ts` says what a request can fill. The rules:
- The first and the last scene are never left out.
- After a scene goes, the scenes on either side must still share at least 3 visible objects (`MIN_SHARED`, the rule templates are authored to), so the Morph stays one piece. A scene the Morph could not bridge is kept.
- **Pre-flight fill check:** the model is told never to invent a figure, a person or a quotation, so a scene built around figures stays empty when the request has none, and a "who is who" scene stays empty when no team is mentioned. Those scenes are left out when the gap can be bridged (the others stay and count against the template in the match score).
- **Shorter decks:** a person may choose a shorter length; only the template's `droppable` scenes (its profile, least important first) go. The reachable lengths run down one at a time. A template with no `droppable` list is offered at its full length only.
- **Plan and credits:** a template longer than the plan's slides per deck is offered shortened, and is set aside only if even its shortest length does not fit (or cannot be paid for at the cheapest model tier).

The job gets the decided list (`options.morphScenes`, written by `startDeckJob`); the pipeline validates it (the template's own order, first and last kept) and writes only those scenes, so the slide count, the credits reserved and the words all follow the same list. `POST /generation/morph-lengths` returns the lengths and the scenes left out for the create page's length buttons (no model call).

### The decision log and the owner's report

Every computed match decision is written to `morph_match_log` (migration 0046): the analysed topic (200 characters), category, language, what was recommended, the candidates and why others were set aside; when the deck is started the row is marked with what it actually used (`markUsed`). Admin → Product → "Morph matches" shows how often a template fit, how often the recommendation was taken, switched or replaced by the AI-planned deck, each template's recommended and started counts, and the topics that got a custom deck (a 140-character excerpt, by category) which is the list of templates to build next. No names, emails or ids leave the report; rows are deleted with the account.

### The custom deck's hand

The custom (AI-planned) Morph has one cast and twelve scenes. It now has a deck-level "hand" (`flip` on the content, chosen from the deck's title by `handOf`, the same on every slide of a deck): in the five scenes that pair the picture with a text column or the cards (cover, hero-left, cards-column, cards-grid, focus-hero) a flipped deck puts the picture on the other side. The cards never change reading order. About half of all decks take each hand. The twelve scenes themselves are still the same arrangements: more variety needs more scene arrangements, not more parameters.
